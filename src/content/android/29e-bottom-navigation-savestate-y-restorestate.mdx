## Concepto

**Qué problema resuelve.** En una app con pestañas, la persona espera que cada pestaña recuerde dónde estaba. Si estaba mirando un detalle en Inicio, pasa a Buscar y vuelve, quiere seguir en el detalle. Y Atrás no debería recorrer todas las pestañas que tocó.

**Antes vs. ahora.** Con Fragments, esto era un clásico doloroso: varios back stacks a mano, `show`/`hide` de Fragments o librerías externas. Desde Navigation 2.4 hay soporte para múltiples back stacks con `saveState` y `restoreState`.

**El patrón completo** (verificado en el test de la lección anterior, escenarios 6 a 8):

```kotlin
fun NavController.irATab(tab: Any) = navigate(tab) {
    popUpTo(graph.findStartDestination().id) { saveState = true }
    launchSingleTop = true
    restoreState = true
}
```

## Ejemplo

Así se usa desde la barra inferior de Material 3:

```kotlin
NavigationBar {
    tabs.forEach { tab ->
        NavigationBarItem(
            selected = destinoActual?.hierarchy?.any { it.hasRoute(tab.ruta::class) } == true,
            onClick = { navController.irATab(tab.ruta) },
            icon = { Icon(tab.icono, contentDescription = null) },
            label = { Text(tab.titulo) },
        )
    }
}
```

`hierarchy` sirve para marcar la tab como seleccionada aunque estés en un detalle dentro de ella.
