## Concepto

**Paso 2: la interfaz de Retrofit y el cliente HTTP.**

> "Describo los dos endpoints como funciones `suspend`. Retrofit las ejecuta fuera del hilo principal, así que el repositorio no necesita cambiar de dispatcher."

> "Configuro un solo `OkHttpClient`, con timeouts explícitos para no depender de los valores por defecto, y el interceptor de logging solo en debug, porque en release imprimiría tokens y datos personales."

En un live coding, la configuración del cliente suele ir directamente en el módulo de Hilt (paso 6), así que acá alcanza con nombrarla.

## Ejemplo

La interfaz:

<pre><code className="language-kotlin">{tareasApi.trimEnd()}</code></pre>

El cliente, tal como está en `di/Modulos.kt`:

```kotlin
@Provides @Singleton
fun okHttp(): OkHttpClient = OkHttpClient.Builder()
    .connectTimeout(10, TimeUnit.SECONDS)
    .readTimeout(15, TimeUnit.SECONDS)
    .apply {
        if (BuildConfig.DEBUG) {
            addInterceptor(HttpLoggingInterceptor().apply { level = HttpLoggingInterceptor.Level.BODY })
        }
    }
    .build()
```

Para usar `BuildConfig.DEBUG`, el módulo activa `buildFeatures { buildConfig = true }`. En los proyectos nuevos viene apagado por defecto.
