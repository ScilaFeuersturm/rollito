## Concepto

Le pediste a la IA: *"Agregá a OkHttp un interceptor que mande el token y lo refresque si vence"*. Te dio esto. Compila, y en una prueba rápida con un solo pedido parece andar.

Este snippet se parece a código real de autenticación, por eso hay que revisarlo con lupa. Hay **seis problemas**, de seguridad, de manejo de recursos, de concurrencia y uno que **compila pero no hace lo que se pidió**.

## Ejemplo

```kotlin
private const val API_KEY = "sk_live_51H8xQ_EJEMPLO"

class AuthInterceptor(private val sesion: Sesion) : Interceptor {
    override fun intercept(chain: Interceptor.Chain): Response {
        val pedido = chain.request().newBuilder()
            .header("Authorization", "Bearer ${sesion.token}")
            .header("X-Api-Key", API_KEY)
            .build()
        val respuesta = chain.proceed(pedido)
        if (respuesta.code == 401) {
            val nuevo: String? = runBlocking { sesion.refrescarToken() }
            return chain.proceed(
                pedido.newBuilder().header("Authorization", "Bearer $nuevo").build()
            )
        }
        return respuesta
    }
}

val cliente = OkHttpClient.Builder()
    .addInterceptor(AuthInterceptor(sesion))
    .addInterceptor(HttpLoggingInterceptor().apply {
        level = HttpLoggingInterceptor.Level.BODY
    })
    .hostnameVerifier { _, _ -> true }
    .build()
```

*Pista:* pensá qué pasa con diez pedidos en paralelo cuando vence el token, y qué pasa si el refresh también falla.
