## Concepto

**Paso 7: navegar al detalle y aceptar un deep link.**

> "Defino las rutas type-safe: `Lista` es un objeto y `Detalle` una data class con el id, las dos `@Serializable`. Paso solo el id, no la tarea entera: los argumentos tienen que ser chicos, y así el detalle funciona igual desde un deep link."

> "El `DetalleViewModel` lee el id del `SavedStateHandle` con `toRoute`. No lo recibe por parámetro, así sobrevive incluso a la muerte del proceso."

> "Declaro el deep link en el destino y en el manifiesto, y lo pruebo con `adb`. Al entrar por el deep link, Navigation arma el back stack con la lista debajo."

## Ejemplo

El grafo de navegación:

<pre><code className="language-kotlin">{navegacion.trimEnd()}</code></pre>

Cómo el ViewModel del detalle obtiene el id (`ui/detalle/DetalleScreen.kt`):

```kotlin
@HiltViewModel
class DetalleViewModel @Inject constructor(
    savedStateHandle: SavedStateHandle,
    private val repo: TareasRepository,
) : ViewModel() {
    private val id = savedStateHandle.toRoute<Detalle>().id
    // ...
}
```

El deep link en el manifiesto:

```xml
<intent-filter>
    <action android:name="android.intent.action.VIEW" />
    <category android:name="android.intent.category.DEFAULT" />
    <category android:name="android.intent.category.BROWSABLE" />
    <data android:scheme="rollito" android:host="tareas" />
</intent-filter>
```

*Las rutas type-safe existen desde Navigation 2.8 y este proyecto compila con la 2.10.2. También existe Navigation 3, con otro modelo: el back stack es una lista que manejás vos. Verificá en developer.android.com cuál usa el equipo.*
