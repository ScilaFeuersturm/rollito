## Concepto

**Qué problema resuelve.** En la entrevista de Hilt casi nunca preguntan la sintaxis. Preguntan "¿qué pasa si…?". Las cinco trampas de esta lección se verificaron compilando con Hilt 2.60.1, y los errores que aparecen son los reales de Dagger.

Todas salen de dos reglas:

1. **Un componente ve lo de sus padres, nunca lo de sus hijos.** `SingletonComponent` no ve nada de Activity, Fragment ni ViewModel.
2. **Un scope largo no puede depender de uno corto.** Si un singleton retuviera algo de Activity, la Activity no se podría liberar: sería una fuga.

**Antes vs. ahora.** En la época de MVP, guardar el `Context` de una Activity en un singleton era una fuga que encontrabas con LeakCanary, en producción. Con Hilt, el mismo error no compila.

## Ejemplo

Los cinco casos, en el orden de los ejercicios:

```kotlin
// 1. IncompatiblyScopedBindings
@ActivityScoped class Carrito @Inject constructor()
@Singleton class Analitica @Inject constructor(val carrito: Carrito)

// 2. MissingBinding (con @ApplicationContext sí compila)
@Singleton class Preferencias @Inject constructor(@ActivityContext val contexto: Context)

// 3. DuplicateBindings: ya hay otro @Provides de OkHttpClient
@Provides fun otroCliente(): OkHttpClient = OkHttpClient()

// 4. MissingBinding: SavedStateHandle solo existe en ViewModelComponent
class BusquedaRepository @Inject constructor(val estado: SavedStateHandle)

// 5. IncompatiblyScopedBindings: un padre no ve a un hijo
@ViewModelScoped class Filtros @Inject constructor()
@Singleton class Historial @Inject constructor(val filtros: Filtros)
```

Leé cada caso y decidí si compila antes de mirar los ejercicios.
