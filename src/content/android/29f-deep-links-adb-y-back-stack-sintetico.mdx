## Concepto

**Qué problema resuelve.** Un link en un mail, una notificación o una web tiene que abrir **una pantalla específica** de la app, con un Atrás que tenga sentido.

**1. Declararlo, en dos lados.**

```xml
<!-- AndroidManifest.xml: qué app abre el link -->
<intent-filter>
    <action android:name="android.intent.action.VIEW" />
    <category android:name="android.intent.category.DEFAULT" />
    <category android:name="android.intent.category.BROWSABLE" />
    <data android:scheme="rollito" android:host="tareas" />
</intent-filter>
```

```kotlin
// En el NavHost: a qué pantalla va. rollito://tareas/7 → Detalle(id = 7)
composable<Detalle>(deepLinks = listOf(navDeepLink<Detalle>(basePath = "rollito://tareas"))) { ... }
```

**2. Probarlo con adb.** `adb shell am start -W -a android.intent.action.VIEW -d "rollito://tareas/7"`. `am start` abre la Activity en una tarea nueva.

**3. El back stack sintético.** Si el link entra en una tarea nueva, Navigation no deja la pila anterior: arma una nueva con el **destino inicial abajo** y el destino del link arriba. Así, Atrás lleva a la pantalla principal en vez de cerrar la app. Está verificado en el escenario 9 de `BackStackTest`: desde `Perfil`, el link deja `Inicio > Detalle(7)`.

## Ejemplo

**Seguridad.** Un deep link es una entrada externa, igual que un pedido HTTP: cualquier app o página puede dispararlo con los parámetros que quiera.

- Validá los parámetros: un id inexistente o con formato inválido tiene que mostrar un error amable.
- Nunca ejecutes una acción sensible (pagar, borrar, transferir) al abrir el link: llevá a una pantalla de confirmación.
- Para links que se comparten, preferí App Links (`https://` + `autoVerify`): Android verifica que el dominio es tuyo.

*Rutas type-safe: existen desde Navigation 2.8, y este proyecto compila con la 2.10.2. También existe Navigation 3, con otro modelo (el back stack es una lista que manejás vos). Verificá en developer.android.com qué usa el equipo.*
