## Concepto

**Qué problema resuelve.** El back stack es la pila de pantallas que recorre el botón Atrás. En entrevista te dan una secuencia de navegaciones y te piden dibujar cómo queda. Las respuestas de esta lección **no son teóricas**: salen de un test que ejecuta cada secuencia con `TestNavHostController` (Navigation 2.10.2) y verifica el resultado.

**Las cuatro herramientas:**

- `navigate(X)`: apila `X`. **Siempre**, aunque ya esté arriba.
- `launchSingleTop = true`: si el tope ya es `X`, no apila otro.
- `popUpTo<Y>()`: antes de navegar, saca todo lo que está **arriba** de `Y`. `Y` queda.
- `popUpTo<Y> { inclusive = true }`: saca también a `Y`.

**Antes vs. ahora.** Con Fragments hacías `replace` + `addToBackStack`, y para limpiar usabas `popBackStack(nombre, POP_BACK_STACK_INCLUSIVE)` o flags de Intent como `FLAG_ACTIVITY_CLEAR_TOP`. Las ideas son las mismas: `popUpTo` equivale al viejo "clear top", y `launchSingleTop`, al modo `singleTop` de una Activity.

## Ejemplo

Escenario base, sin opciones:

```kotlin
// Arranca en Inicio
navController.navigate(Detalle(1))
navController.navigate(Detalle(2))
navController.navigate(Detalle(2))
// Back stack: Inicio > Detalle(1) > Detalle(2) > Detalle(2)
```

Y el flujo de login bien hecho:

```kotlin
navController.navigate(Inicio) {
    popUpTo<Login> { inclusive = true }
}
// Back stack: Inicio  (Atrás cierra la app, no vuelve al login)
```

Predecí cada escenario de los ejercicios antes de mirar las opciones. Los diez escenarios verificados están en `android-samples/live-coding/app/src/test/java/com/rollito/livecoding/ui/BackStackTest.kt`.
