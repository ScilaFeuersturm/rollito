## Concepto

**Qué problema resuelve.** Los access tokens duran poco (minutos u horas). Cuando vencen, el backend responde 401, y la app tiene que conseguir uno nuevo con el refresh token y repetir el pedido, sin que la persona se entere. Hecho mal, aparecen los bugs del code review 3: `Bearer null`, bucles de 401, diez refreshes simultáneos.

**Dos piezas, cada una con un trabajo:**

- **`AuthInterceptor`:** agrega `Authorization: Bearer <token>` a cada pedido. Nada más.
- **`TokenAuthenticator`:** OkHttp lo llama **solo ante un 401**. Refresca, devuelve el pedido con el token nuevo y OkHttp lo reintenta. Si devuelve `null`, OkHttp se rinde y entrega el 401.

**Tres detalles que piden en entrevista:**

1. **Un solo refresh** aunque lleguen varios 401: bloque sincronizado y "¿otro hilo ya lo refrescó?".
2. **Si el refresh falla, `null`**: nunca `Bearer null` ni el mismo pedido.
3. **Contar los intentos** con `priorResponse`, para no entrar en un bucle.
