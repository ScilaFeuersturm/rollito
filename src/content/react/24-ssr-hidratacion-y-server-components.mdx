## Concepto

**Qué problema resuelve.** En una SPA clásica, el navegador recibe un HTML vacío, descarga el JavaScript y recién ahí dibuja: la primera pantalla tarda, y los buscadores ven poco.

- **SSR o prerenderizado:** el servidor (o el build) genera el HTML de cada página. Se ve enseguida.
- **Hidratación:** React se conecta a ese HTML existente con `hydrateRoot`, en vez de crearlo con `createRoot`.
- **Server Components:** componentes que corren solo en el servidor; su código nunca llega al navegador.

## Ejemplo

Rollito usa prerenderizado: cada página se genera como HTML en el build y el navegador la hidrata. Así decide qué hacer (`src/entry-client.tsx`):

```tsx
const prerendered = root.dataset.route
if (prerendered && sameRoute(prerendered, location.pathname)) {
  hydrateRoot(root, app)           // el HTML coincide: se hidrata
} else {
  root.replaceChildren()
  createRoot(root).render(app)     // no coincide: se dibuja desde cero
}
```

Y así evita el error de hidratación con el progreso, que vive en el navegador (`src/app/App.tsx`):

```tsx
// El servidor no tiene localStorage: arrancamos vacío en los dos lados para que el HTML
// prerenderizado coincida con el primer render del cliente, y recién después leemos el progreso.
const [progress, setProgress] = useState<Progress>({})
useEffect(() => setProgress(readProgress()), [])
```
