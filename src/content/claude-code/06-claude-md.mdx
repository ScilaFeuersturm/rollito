## Concepto

**Qué problema resuelve.** Cada sesión empieza sin recordar las anteriores. El `CLAUDE.md` es lo que Claude lee siempre al arrancar: los comandos del proyecto, las convenciones y las reglas del equipo. Así no tenés que repetirlas.

**Dónde puede estar:**

- `~/.claude/CLAUDE.md`: tuyo, para todos tus proyectos.
- `./CLAUDE.md` o `./.claude/CLAUDE.md`: del proyecto. Se commitea.
- `./CLAUDE.local.md`: tuyo, solo este proyecto. Va al `.gitignore`.
- En una subcarpeta: se carga cuando Claude trabaja con archivos de esa carpeta.

**Importar otros archivos:** dentro del `CLAUDE.md` podés escribir `@docs/flujo-de-git.md` y se incluye ese archivo.

**Qué poner** (consejos de la documentación): comandos, convenciones y estructura; reglas concretas; sin contradicciones; menos de 200 líneas. Si un repo tiene `AGENTS.md` y no tiene `CLAUDE.md`, Claude lee el `AGENTS.md`.

## Ejemplo

Un `CLAUDE.md` corto y útil:

```markdown
# Rollito

## Comandos
- `npm test`: tests con Vitest
- `npm run build`: chequeo de tipos, build y prerender (tiene que pasar antes de pushear)

## Convenciones
- Textos en español rioplatense, con voseo.
- Las lecciones van en `src/content/<track>/` como .mdx; el frontmatter lo valida `lesson-schema.ts`.
- No commitear nada de la carpeta `privado/`.
```
