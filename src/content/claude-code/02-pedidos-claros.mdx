## Concepto

**Qué problema resuelve.** La diferencia entre quien "maneja bien" Claude Code y quien no casi nunca es un truco técnico: es cómo pide las cosas. Un pedido vago hace que Claude adivine, y ahí aparecen las idas y vueltas.

**Las tres partes de un buen pedido** (así lo recomienda la documentación oficial):

1. **Dónde:** el archivo o la pantalla. Con `@` autocompletás la ruta.
2. **Qué pasa:** el síntoma concreto, o lo que querés lograr.
3. **Qué es "listo":** cómo te vas a dar cuenta de que está bien. Ideal: algo que se puede correr y da verde o rojo, como un test.

**Más contexto, menos adivinanza:**

- **Capturas:** pegá la captura de un diseño o de un error con `Ctrl+V` (en Windows también `Alt+V`).
- **Salidas de comandos:** `! npm test` ejecuta el comando y su salida queda en la conversación.
- **Pedí evidencia** al final: el comando y su salida.

## Ejemplo

Pedido vago:

```text
arreglá el login
```

Pedido claro:

```text
En @src/app/Cuenta.tsx, cuando el código de invitación es inválido la pantalla
queda en "Un momento…". Tiene que mostrar "El código de invitación no es válido"
y volver a habilitar el botón. Corré npm test al final y mostrame la salida.
```
