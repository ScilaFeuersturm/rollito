## Concepto

**Qué problema resuelve.** Hay pasos que tienen que pasar **siempre**: formatear, correr el linter, bloquear un comando peligroso. Como instrucción en el `CLAUDE.md`, Claude puede olvidarlos; como hook, los ejecuta el programa.

**Eventos más usados:**

- `PreToolUse`: antes de usar una herramienta. Puede bloquearla.
- `PostToolUse`: después de usarla. Ideal para formatear o hacer lint.
- `UserPromptSubmit`: cuando mandás un pedido.
- `SessionStart`: al empezar la sesión.
- `Stop`: cuando Claude termina de responder.
- `Notification`: cuando Claude te necesita.

**Dónde van:** en los mismos archivos de configuración (`~/.claude/settings.json`, `.claude/settings.json`, `.claude/settings.local.json`), y se suman entre niveles. `/hooks` muestra los que están cargados y de dónde vienen.

## Ejemplo

El ejemplo de la documentación oficial: formatear con Prettier después de cada edición. El hook recibe por stdin un JSON con los datos de la herramienta, y `jq` saca la ruta del archivo:

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "f=$(jq -r '.tool_input.file_path') && npx prettier --write --ignore-unknown \"$f\""
          }
        ]
      }
    ]
  }
}
```

Necesita `jq` instalado. En Windows, la documentación muestra hooks que llaman a `powershell.exe` con un script `.ps1`.
