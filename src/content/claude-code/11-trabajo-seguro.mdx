## Concepto

**Qué problema resuelve.** Claude Code trabaja en tu máquina, con tus archivos y tus credenciales. Eso lo hace muy útil y, al mismo tiempo, pide criterio.

**Cuatro hábitos:**

1. **Secretos fuera de su alcance:** reglas de deny para `.env` y similares, y nada de secretos en el código.
2. **Permisos acotados:** allow para lo que usás seguido (`npm test`), no para todo. `bypassPermissions`, solo en entornos aislados.
3. **Revisar antes de commitear:** `/diff`, los tests y, si importa, una segunda opinión (sesión nueva o subagente revisor).
4. **Elegir el esfuerzo:** `/model` cambia el modelo y `/effort` el nivel de razonamiento. Para tareas simples alcanza con poco; para un problema difícil, más.

## Ejemplo

Una configuración de proyecto prudente, en `.claude/settings.json`:

```json
{
  "permissions": {
    "allow": ["Bash(npm test)", "Bash(npm run build)", "Bash(git status)", "Bash(git diff *)"],
    "deny": ["Read(./.env)", "Read(./.env.*)", "Read(./privado/**)", "Bash(git push *)"]
  }
}
```

Con esto, Claude corre los tests y el build sin preguntar, nunca lee secretos ni la carpeta privada, y el push lo hacés vos.
