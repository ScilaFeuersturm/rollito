## Concepto

**Qué problema resuelve.** Si todos los días le pedís lo mismo con las mismas palabras (revisar un PR, preparar un commit, generar un test), conviene escribirlo una vez como skill y llamarlo con `/nombre`.

**Dónde van:**

- Proyecto (equipo): `.claude/skills/<nombre>/SKILL.md`. Se commitea.
- Personal: `~/.claude/skills/<nombre>/SKILL.md`.
- Los archivos viejos de `.claude/commands/` siguen funcionando.

**Frontmatter más usado:**

- `description`: qué hace y cuándo usarla. Es lo que Claude lee para decidir si aplicarla.
- `disable-model-invocation: true`: solo vos la podés disparar.
- `argument-hint`: el texto de ayuda que aparece al escribir el comando, por ejemplo `[numero-de-issue]`.
- `allowed-tools`: herramientas que puede usar sin pedir permiso mientras corre la skill.

## Ejemplo

El ejemplo mínimo de la documentación oficial, en `.claude/skills/fix-issue/SKILL.md`:

```markdown
---
name: fix-issue
description: Fix a GitHub issue
disable-model-invocation: true
---

Fix GitHub issue $ARGUMENTS following our coding standards.
```

Con `/fix-issue 123`, el `123` llega en `$ARGUMENTS`. Las instrucciones pueden estar en español.
