## Concepto

**Qué problema resuelve.** ¿Cómo sabés si tus tests son buenos? La cobertura es la respuesta fácil, pero engañosa.

- **Cobertura:** qué porcentaje del código se ejecuta durante los tests (líneas, ramas). Sirve para encontrar código sin probar.
- **Mutation testing:** cambia el código de a poco (mutantes) y comprueba si algún test falla. Si ninguno falla, ese comportamiento no está verificado. Mide la **calidad** de los tests, no solo cuánto ejecutan.

## Ejemplo

Una ronda de mutation testing hecha a mano sobre `src/cuenta/validar.ts`, al preparar esta lección:

- `limpio.length > 60` → `>= 60`: **detectado** (falla el caso de 60 caracteres).
- `limpio.length === 0` → `< 0`: **detectado** (falla el caso del nombre vacío).
- Sacar el `trim()`: **detectado** (fallan dos casos, incluido el de solo espacios).
- `clave.length < 8` → `<= 8`: **detectado** (falla el caso de 8 caracteres).

Los cuatro mutantes murieron porque los tests usan valores límite. Es la conexión entre la técnica del nivel Junior y la calidad de la automatización.
