## Concepto

**Qué problema resuelve.** El software lo escriben personas, y las personas se equivocan. El testing busca esos errores **antes** de que los encuentre alguien que usa la app, cuando arreglarlos sale más caro.

Tres palabras que se confunden:

- **Error (o equivocación):** lo que hace una persona, por ejemplo entender mal un requisito.
- **Defecto (bug):** el problema que queda en el código o en la configuración.
- **Falla:** lo que se ve cuando ese defecto se ejecuta: un crash, un mensaje equivocado, un dato mal guardado.

Y una idea central: **testing no es solo "hacer clic hasta que algo se rompa"**. Es elegir qué probar, con qué datos y en qué orden, según el riesgo.

## Ejemplo

Una falla real de este mismo sitio: durante varias horas, Rollito no se publicaba aunque el código estaba bien en la máquina de quien lo escribía.

- **Error:** una regla del `.gitignore` pensada para una carpeta excluía también otra con el mismo nombre.
- **Defecto:** un archivo que el sitio necesita nunca llegó al repositorio.
- **Falla:** el servidor fallaba al construir el sitio y seguía mostrando la versión vieja.

Se encontró revisando el estado del deploy, no el código: probar también es mirar dónde corre el software de verdad.
