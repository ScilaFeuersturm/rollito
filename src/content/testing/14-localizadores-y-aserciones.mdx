## Concepto

**Qué problema resuelve.** Los tests E2E se rompen por dos motivos típicos: localizadores frágiles (que dependen del CSS o de la estructura) y esperas mal hechas. Playwright resuelve las dos.

**Localizadores, en orden de preferencia:**

1. `getByRole('button', { name: 'Entrar' })`
2. `getByLabel('Nombre')`
3. `getByText('limitada al equipo')`
4. `getByTestId('contenedor')`, si no hay otra forma.

**Modo estricto:** si un localizador encuentra varios elementos y le pedís una acción, falla en vez de elegir uno al azar.

**Aserciones web-first:** `toBeVisible`, `toHaveText` o `toHaveURL` reintentan hasta que se cumplan.

## Ejemplo

El caso real de Rollito. Primero:

```ts
page.getByRole('button', { name: 'Entrar', exact: true })
// Error: strict mode violation: ... resolved to 2 elements:
//   1) <button aria-pressed="true">Entrar</button>  (la opción)
//   2) <button>Entrar</button>                       (enviar el formulario)
```

Después, acotado al grupo de opciones:

```ts
page.getByRole('group', { name: '¿Qué querés hacer?' }).getByRole('button', { name: 'Entrar', exact: true })
```

El grupo tiene ese nombre porque el componente usa `role="group"` con `aria-label`: un localizador por rol funciona bien cuando la pantalla es accesible.
