## Concepto

**Qué problema resuelve.** Los tests E2E más inestables suelen fallar por los datos y la red: un usuario que otro test borró, un servicio externo caído, una base con basura de corridas anteriores.

- **Aislamiento:** cada test prepara su estado y no depende del orden.
- **Red simulada:** `page.route()` para bloquear o responder pedidos (`route.abort()`, `route.fulfill()`).
- **Entornos de prueba:** emuladores (como el de Firebase) o una base que se reinicia, nunca producción.
- **Sesiones guardadas:** `storageState` para no hacer login por la pantalla en cada test.

## Ejemplo

En `CuentaPage.abrir()`:

```ts
await this.page.route(/googleapis\.com|firebaseapp\.com/, ruta => ruta.abort())
```

Así, el test del nombre vacío confirma que la validación ocurre **antes** de llamar a Firebase: si el código intentara crear la cuenta, el pedido se cortaría y aparecería otro mensaje.

Para simular un estado difícil de conseguir, por ejemplo un servidor caído:

```ts
await page.route('**/todos', ruta => ruta.fulfill({ status: 500, json: {} }))
```
