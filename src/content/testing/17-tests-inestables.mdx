## Concepto

**Qué problema resuelve.** Un test que falla de vez en cuando es peor que no tenerlo: entrena al equipo a ignorar las fallas.

**Causas típicas y cómo evitarlas:**

- **Esperas fijas** (`waitForTimeout`) → esperar condiciones con aserciones web-first.
- **Datos compartidos** entre tests → cada test prepara los suyos.
- **Servicios externos** → simularlos o usar un emulador.
- **Orden de ejecución** → los tests no dependen unos de otros.
- **Animaciones y tiempos** → esperar el estado final, no el intermedio.

**Cuando aparece uno:** se investiga con la traza, se arregla o se pone en cuarentena (se marca y se excluye temporalmente) con un responsable.

## Ejemplo

La configuración de Rollito para la CI:

```ts
retries: process.env.CI ? 2 : 0,      // en tu máquina, sin reintentos: querés ver la falla
use: { trace: 'on-first-retry' },     // si se reintenta, queda la traza para investigar
```

Y una práctica para detectarlos antes de mergear: correr el test nuevo muchas veces seguidas.

```text
npx playwright test e2e/sitio.e2e.ts --repeat-each=20
```
