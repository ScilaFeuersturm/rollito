## Concepto

**Qué problema resuelve.** La seguridad no es solo de especialistas: muchos de los problemas más graves se encuentran con pruebas simples, si se piensan.

**OWASP Top 10** es la lista de referencia de los riesgos más comunes en aplicaciones web (verificá la edición vigente). Algunos que todo QA puede probar:

- **Control de acceso roto:** ver o hacer lo que no te corresponde (IDOR, funciones de admin).
- **Inyección y XSS:** datos que se ejecutan como código.
- **Fallas de autenticación:** sesiones que no expiran, recuperación de contraseña que revela información.
- **Configuración insegura:** mensajes de error con detalles internos, secretos expuestos.

**Herramientas:** OWASP ZAP o Burp Suite para analizar y modificar el tráfico.

## Ejemplo

Las pruebas de seguridad reales de Rollito, en las reglas de Firestore (21 casos contra el emulador): un código usado no sirve dos veces, nadie lee ni escribe el progreso ajeno, una cuenta sin invitación no guarda nada y nadie se nombra admin.

Y dos pruebas más que se hicieron:

- **XSS:** la lección Senior de seguridad de React verifica con un test que el texto se escapa y que React 19 bloquea los `href="javascript:…"`.
- **Enumeración de cuentas:** "Olvidé mi contraseña" muestra el mismo mensaje exista o no el mail, para no revelar quién tiene cuenta.

Y un hallazgo pendiente: la contraseña de 8 caracteres se valida en la app, pero Firebase acepta 6; hay que configurar la política también en el servidor.
