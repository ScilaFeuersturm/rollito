## Concepto

**Qué problema resuelve.** Una app y su backend evolucionan por separado. Los tests de cada lado pasan, pero juntos se rompen: un campo renombrado, un tipo que cambió, un campo que dejó de venir.

- **Contrato:** qué pedidos hace el consumidor y qué respuestas espera.
- **Lado del consumidor:** sus tests corren contra un servidor simulado que registra el contrato.
- **Lado del proveedor:** el backend verifica que cumple todos los contratos de sus consumidores.
- **Herramientas:** Pact es la más conocida; también hay enfoques con esquemas (OpenAPI) compartidos.

## Ejemplo

En el live coding de Android y de React, el contrato está implícito en el DTO:

```ts
type TareaDto = { id: number; title: string; completed: boolean }
```

Y la guardia `esTareaDto` lo verifica en tiempo de ejecución: si el backend cambia la forma, la app muestra un error controlado en vez de romperse. Eso protege a la persona, pero el problema se descubre en producción.

Con contract testing, ese mismo contrato se comparte con el backend, y un cambio incompatible falla en **su** CI, antes de desplegar.
