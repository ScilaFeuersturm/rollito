## Concepto

**Qué problema resuelve.** La API es la frontera real del sistema: todo lo que la pantalla valida, la API lo tiene que validar de nuevo. Probarla directamente es más rápido y estable que hacerlo desde la UI.

- **Camino feliz:** código de estado y forma de la respuesta.
- **Casos negativos:** sin autenticación, sin permisos, datos inválidos, recursos inexistentes.
- **Contrato:** que la forma de la respuesta no cambie sin aviso.
- **Herramientas:** Postman o Bruno para explorar; código (Vitest, Playwright `request`, REST Assured) para automatizar.

## Ejemplo

Rollito no tiene una API propia, pero sus reglas de Firestore funcionan como una: deciden quién puede leer y escribir qué. Están probadas como una API, con casos negativos, contra el emulador (`firebase/reglas.emulador.mjs`):

- Un código ya usado no sirve para otra persona.
- Nadie lee ni escribe el progreso de otra persona.
- Una cuenta sin invitación no puede guardar progreso.
- Nadie se puede nombrar admin desde la app.
- Un nombre vacío no se acepta (el caso que apareció con el bug del registro).

De 21 casos, la mayoría son negativos: así se prueba la seguridad.
