## Concepto

**Qué problema resuelve.** Una de cada seis personas tiene algún tipo de discapacidad, y la accesibilidad además es un requisito legal en muchos lugares. Se prueba en dos capas:

- **Automática (axe, Lighthouse):** contraste, labels, roles, atributos ARIA inválidos. Rápida, va en la CI.
- **Manual:** teclado, lector de pantalla, zoom, fuente grande y comprensión. Encuentra lo que las reglas no ven.

La referencia es WCAG (Web Content Accessibility Guidelines), con niveles A, AA y AAA; el objetivo habitual es AA.

## Ejemplo

El test real de Rollito, en `e2e/sitio.e2e.ts`:

```ts
test('no tiene problemas de accesibilidad detectables automáticamente', async ({ page }) => {
  await page.goto('/')
  await expect(page.getByText('limitada al equipo de Taller Fichín')).toBeVisible()
  const resultado = await new AxeBuilder({ page }).analyze()
  expect(resultado.violations.map(v => `${v.id}: ${v.help}`)).toEqual([])
})
```

Corre en escritorio y en celular. Y un hallazgo manual que axe no habría encontrado: las opciones de la pantalla de cuenta **no parecían botones**. El equipo lo notó usándola, y la corrección sumó `aria-pressed` para que el lector de pantalla anuncie cuál está elegida.
