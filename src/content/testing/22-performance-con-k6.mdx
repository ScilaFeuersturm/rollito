## Concepto

**Qué problema resuelve.** Una funcionalidad puede andar perfecto con una persona y caerse con cien. Las pruebas de performance responden: ¿cuánto aguanta y qué tan rápido responde bajo carga?

- **Carga:** el uso esperado, contra objetivos (por ejemplo, p95 menor a 500 ms con 200 usuarios).
- **Estrés:** subir hasta romper, para conocer el límite.
- **Picos y resistencia:** subidas bruscas y carga sostenida.
- **Métricas:** percentiles de tiempo de respuesta (p95, p99), tasa de errores y pedidos por segundo.

**k6** escribe las pruebas en JavaScript y define los objetivos como `thresholds` que hacen fallar la prueba.

## Ejemplo

Un script de k6 de referencia (verificá la sintaxis vigente en la documentación de k6). Ojo: corrélo contra un entorno tuyo, no contra un servicio de terceros.

```js
import http from 'k6/http'
import { check, sleep } from 'k6'

export const options = {
  stages: [
    { duration: '1m', target: 50 },   // sube a 50 usuarios virtuales
    { duration: '3m', target: 50 },   // los mantiene
    { duration: '1m', target: 0 },    // baja
  ],
  thresholds: {
    http_req_duration: ['p(95)<500'], // el 95% responde en menos de 500 ms
    http_req_failed: ['rate<0.01'],   // menos del 1% de errores
  },
}

export default function () {
  const respuesta = http.get('https://staging.ejemplo.com/api/tareas')
  check(respuesta, { 'responde 200': r => r.status === 200 })
  sleep(1)
}
```

Para el frontend, el equivalente es medir en el navegador: Lighthouse y las Core Web Vitals (LCP, INP, CLS).
